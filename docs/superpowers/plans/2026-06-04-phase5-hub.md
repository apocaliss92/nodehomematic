# nodehomematic — Phase 5: Hub (sysvar, programs) + rooms/functions via ReGa

> **For agentic workers:** TDD module-by-module. Builds on Phases 1–4 (merged, 0.2.0). Adds the hub layer (system variables + programs) to the facade, and fixes the Phase-2 rooms/functions gap with a custom ReGa script keyed by channel address.

**Goal:** Expose on the `Homematic` facade: system variables (list, read, write) and programs (list, run, activate/deactivate). Also populate the devices' `rooms`/`functions` via a **custom ReGa script** (channel-address-keyed), resolving the Phase 2 gap.

**Architecture:** A `ReGaRunner` runs ReGa scripts via JSON-RPC `ReGa.runScript` (param `script` = body, `##key##` substitution, result = a JSON string to re-parse + control-char sanitize; UriEncoded names → latin1 decode). A `HubFetcher` uses JSON-RPC (`SysVar.*`, `Program.*`) + ReGa for sysvars/programs/descriptions. Rooms/functions are read from a custom ReGa script and merged into the `DeviceNode`. The facade exposes immutable snapshots + commands.

**Tech Stack:** strict TypeScript. Tests: vitest + FakeCcu (extend the JSON-RPC: SysVar.*, Program.*, ReGa.runScript) + real e2e (the real sysvars/programs/rooms).

## Facts (from aiohomematic — authoritative)

### ReGa.runScript
- JSON-RPC method `ReGa.runScript`, param key **`script`** = the whole body. Placeholder `##key##` substitution → value (ReGa escape: `\`→`\\`, `"`→`\"`). The `result` is a **JSON string** → sanitize unescaped control-chars → `JSON.parse`. `UriEncode`d names/descriptions → `decodeURIComponent` in **latin1/ISO-8859-1**.

### System variables
- `SysVar.getAll` → entry `{ id, name, type, value, unit, isInternal, valueList ("a;b;c"), minValue?, maxValue? }`. No description (separate).
- `HubValueType`: ALARM, FLOAT, INTEGER, LIST, LOGIC, NUMBER, STRING. Normalize NUMBER→FLOAT if the value contains `.`, otherwise INTEGER.
- Value parse: ALARM/LOGIC→bool (`to_bool`: y/yes/t/true/on/1); FLOAT→number; INTEGER/LIST→int; STRING/NUMBER→passthrough.
- Single read: `SysVar.getValueByName {name}`.
- Write (dispatch on the JS VALUE type): bool→`SysVar.setBool {name, value:0|1}`; string→**ReGa** `set_system_variable.fn`; numeric→`SysVar.setFloat {name, value}`.
- Descriptions: ReGa `get_system_variable_descriptions.fn` → `[{id, description}]`. The **`HAHM`** marker in the description = `extended_sysvar` = WRITABLE sysvar; without the marker = read-only sensor.

### Programs
- `Program.getAll` → `{ id, name, isActive, isInternal, lastExecuteTime }`.
- `Program.execute {id}`. Activate/deactivate: ReGa `set_program_state.fn` `{id, state:"1"|"0"}`.

### Rooms/functions (Option B — custom ReGa script, channel-address-keyed)
- ReGa primitives (from `get_service_messages.fn`): `object oChn = dom.GetObject(iChnId); oChn.Address()` → "ABC123:1"; `foreach(sRoomId, oChn.ChnRoom()) { dom.GetObject(sRoomId).Name() }`; `foreach(sFuncId, oChn.ChnFunction()) { ... }`.
- Write a script that enumerates the channels and emits JSON `{ "<channelAddress>": ["RoomName", ...] }` for rooms and likewise for functions (UriEncode the names). Invoke via `ReGa.runScript`.

JSON output `{"rooms":{addr:[names]},"functions":{addr:[names]}}`.
